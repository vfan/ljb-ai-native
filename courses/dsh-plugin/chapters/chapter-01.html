CHAPTER 01 · PLUGIN / TRUST BOUNDARY

01

插件是什么，
什么时候该写插件

先判断该不该写插件：接入方式决定方案，维护成本决定取舍。

本章目标

  • 判断一个需求应该用什么方案实现（脚本、Skill、插件，还是修改宿主源码）。
  • 说清楚安装一个插件意味着承担什么信任与安全责任。

第 1 节

从一个提醒需求开始

你让 AI 编程助手修改功能。它正在读代码、改文件、运行测试。你切到其他窗口，回来后才发现：AI 已经停了几分钟，正在等待你确认操作。

于是有了一个需求：

任务结束，或者需要用户作决定时，自动提醒。

如果只想在某一次任务完成后播放声音，可以让 Agent 执行播放脚本。但如果希望各种任务都能自动提醒，就需要一个可靠的触发机制：

问题需要的能力
什么时候提醒？识别运行状态的变化
怎样提醒？播放声音或显示通知
怎样避免重复提醒？记录已经处理过的状态
用户怎样调整？提供开关、音量等配置

宿主已有功能或钩子可能满足需求；如果没有，可以研究插件扩展。

第 2 节

什么是插件？

插件是宿主应用按照约定加载的扩展单元，用来增加或改变应用的能力。 一个扩展单元通常是一段程序，也可以只是组合已有插件的纯配置包。

宿主就是加载并运行插件的应用。

宿主应用插件功能示例
浏览器翻译网页、管理标签页
代码编辑器格式化代码、显示 Git 历史
DeepSeek Harness（命令为 dsh）增加工具、通知、界面和服务

宿主通过扩展接口让插件参与运行；插件则遵守入口、依赖、配置和加载方式等约定。一段代码只有被宿主正确加载，才能作为插件发挥作用。

dsh 用 Cordis 作为插件框架组织插件，其许多内置能力也由插件组合而成。

插件可以同时包含多种能力：

类型作用示例
工具扩展增加 Agent 可以调用的操作查询天气、读取特定数据
事件响应在某件事发生时执行程序工具执行后记录日志
界面扩展增加用户可操作的界面设置面板、侧边栏按钮
服务扩展提供其他插件可使用的程序能力统一的数据访问服务

第 3 节

安装插件意味着什么？

安装插件是在引入程序代码，需要信任它的来源和行为。

执行位置需要理解的边界
安装脚本可能在安装阶段执行代码
Host：宿主端以宿主进程权限运行，可读写文件、启动进程、访问网络，不经过 Agent 工具审批路径
Client：客户端在浏览器页面环境中运行，受浏览器规则限制
Agent 工具调用按对应的工具执行与策略机制处理

使用第三方插件前应确认：来源是否可信、需要哪些能力、安装的版本或提交、是否兼容当前 dsh 版本。

第 4 节

插件、Skill、工具、MCP、CLI 的关系

Skill 主要提供 Agent 做事的方法和资源；插件是宿主加载的程序扩展。 两者可以配合——插件还可以包含并注册 Skill（作为 Skill 的载体）。

概念本质主要作用
Skill方法、规则和配套资源指导任务怎样完成
工具一项可调用操作执行具体动作
MCP应用连接外部能力的协议规范能力发现与交互
CLI程序的命令行接口通过命令执行操作
插件宿主加载的扩展单元为应用接入能力或行为

同样能播放声音，实现方式却不同：

比较项Skill 配合播放脚本自动提醒插件
谁触发？Agent 按流程执行程序根据状态或事件执行
是否依赖模型执行这一步？通常依赖可以不依赖
是否能提供设置界面？需要其他机制配合可以接入宿主 UI 扩展接口

这不是"哪个更高级"，而是触发机制与集成方式不同。它们不是五选一，而是可以组合的不同部分。

插件安装后，也不一定出现在模型工具列表中：触发方式可以是模型调用、程序响应事件、用户操作界面或定时执行。没有模型参与的程序逻辑本身不需要模型，但插件提供的工具描述、提示内容仍可能带来 Token 开销。

第 5 节

什么时候该写插件——先看能力，再看成本

1. 能力边界：三个案例

案例一：批量转换视频。 已有 FFmpeg 和终端执行能力时，用 Skill 描述流程 + CLI 执行即可，不需要专门开发 dsh 插件。

案例二：在工具结果旁固定显示按钮。 这改变宿主界面，Skill 做不到。路径：已有按钮直接用 → 有 UI 扩展接口写插件 → 都没有则改宿主源码或调整方案。

案例三：各种任务都自动提醒。 单独的播放命令只负责"发出声音"，不负责识别"什么时候该响"。先检查宿主是否已有提醒设置或运行钩子；没有，再研究插件。

选择插件的依据，是需要怎样接入应用，而不是任务看起来有多复杂。

2. 成本清单：写插件的代价

能力上"能做"，不代表"值得做"。决定动手前，把这些成本摆上桌：

成本项说明
版本跟进宿主接口（事件签名、插槽名、路由契约）可能随版本变化，插件要跟着维护
运行开销事件监听在宿主进程内执行，高频事件上的重逻辑会拖慢宿主
兼容声明每个版本都要记录"实际验证过的范围"，不能笼统说"兼容"
安全责任Host 插件以进程权限运行，出错或被滥用的后果由插件承担
卸载语义要自己定义清楚：卸载撤销什么、保留什么，用户数据怎么处理

一个生命周期只有两周的一次性任务，写插件的维护成本几乎一定高于写一个脚本。

第 6 节

练习

不写代码，判断下面三个需求该用什么方案，并说明理由：

  1. 把当前会话导出成 PDF。
  2. 每天早上九点自动拉取公司内部系统数据，汇总后发送邮件。
  3. 在 dsh 设置页增加一个"默认音量"滑块。

完成后回答：

  1. 插件和 Skill 的触发机制有什么不同？
  2. 安装一个 Host 插件，等于给了它什么权限？
  3. "能做"和"值得做"之间隔着哪五项成本？

本章带走句

先问"该不该"，再问"怎么写"——接入方式决定方案，维护成本决定取舍；装插件就是给它宿主进程权限。
