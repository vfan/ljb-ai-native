配置、状态

第 1 节

问题对应概念

第 2 节

核心概念

1. 配置描述"应该怎样运行"（以及它从哪来）

先回答一个上一章埋下的问题： 前 4 章的入口都写作 apply(ctx)，本章开始出现 apply(ctx, config)。config 是框架传入的第二个参数：框架加载插件时，读取你导出的 Config Schema，校验 YAML 中该条目下的 config 字段、填入默认值，然后把结果作为 config 传给 apply。没有导出 Config 的插件，config 就是空对象。

配置是用户在加载前给出的选择；不是所有内部变量都适合做配置——会改变使用方式的（前缀、过滤、开关）交给用户，实现细节（监听哪个事件、如何拼日志）由开发者决定。

框架用 Schema 校验配置，导出有两部分（TypeScript 允许类型和值同名）：

声明作用
export interface Config开发时描述字段类型，检查源码
export const Config: Schema<Config>运行时校验 YAML、填充默认值

只写接口不够：接口不会检查用户实际填写的 YAML，enabled: '随便写' 只有运行时 Schema 能发现。类型检查面对源码，配置校验面对实际输入。

Schema 的 default() 只在字段缺失时生效。onlyTool 默认空字符串，而"空字符串表示不过滤"是本例程序自己的约定，不是框架赋予的含义。

2. 配置不是状态

比较项配置状态
来源用户或部署设置程序运行过程
例子日志前缀、过滤条件已记录次数、当前播放状态
改变原因调整使用方式发生了新操作
本例位置YAML 与加载后的配置对象插件实例内存

let count = 0 是状态：每次 apply 都创建新的计数器，重启归零。状态还要选对范围——把"某会话是否已提醒过"做成全局 let notified = false，会话 A 就会影响会话 B。需要持久化时先回答：哪个会话累计还是工作区累计还是跨重启累计？谁更新？并发怎么合并？先决定数据的归属和生命周期，再选择存储方式，不要为了"下次还能看到"就把状态写回配置文件。

3. profile、bundle 与 patch

概念含义
profile一套可以启动的插件组合（运行配置）
bundle可安装、可分发的一层配置及相关代码（组合包）
patch对插件组合做插入或覆盖的配置操作（补丁）

配置按顺序叠加：bundle 层 → profile 自身补丁 → home 层补丁（$DSH_HOME 默认 ~/.dsh，可用环境变量覆盖）→ 命令行 --patch。后层覆盖前层。

替换一个条目的 config 是整体替换，不是逐字段深合并。 后一层没写的字段会回落到 Schema 默认值，而不是保留前一层同名字段的值。前层写了 prefix 和 onlyTool，后层只写 prefix，onlyTool 就变回默认空字符串。排查"配置改了没效果"，要看最终生效的组合，不要只看某一个文件。

4. UI 位置由插槽契约决定

"插件在哪里"是三个问题：代码在哪（路径）？是否启用（组合）？显示在哪（插槽注册）。文件路径负责让程序被找到，插槽注册负责让组件被展示。

插槽是宿主明确开放的界面扩展位置。位置不能凭名字猜，必须查目标插槽的契约：

  • 会话界面：packages/client/ui-conversation/src/client/contract/slots.ts。conversation.session.header.actions（list、session，会话标题旁）、conversation.composer.dock（list、session，输入框卡片下方，适合放统计、状态等环境信息）。
  • 设置页面：packages/client/ui-settings/src/client/contract/slots.ts。settings.section（list、root，一整页设置）；settings.general.item（list、root，General 分区的一行偏好，文案、当前值和写入路径都由注册者负责）。
  • 工作区：packages/client/ui-workspace/src/client/contract/slots.ts（其 README 只描述它自己那一侧的位置，不能用来解释会话标题栏或设置页）。

注册机制三件事不要混：

  • inject: ['slots']：Cordis 服务依赖，不决定位置。
  • ctx.slots.inject(name, cb)：等宿主声明目标插槽后再执行回调，解决时序，不决定位置。
  • ctx.slots.register({ name, id, order }, Component)：把组件放进插槽。

5. 配置界面 ≠ 配置已保存

界面能响应操作，只证明组件在工作；不证明值已写入、会被读取、刷新后恢复。从拖动到真正保存要经过四步：更新显示 → 更新当前行为 → 保存（刷新后可恢复）→ 同步到其他页面。每个配置项都要写清：谁保存、谁读取、什么时候应用。Host 与 Client 各有一个 volume 变量不会自动同步，必须走宿主通信机制。

第 3 节

操作与预期结果

1. 给日志插件加配置

替换 tool-logger.ts：

TypeScript
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'
import '@deepseek-ai/dsh-tools'

export const name = 'tool-logger'

export interface Config {
  enabled: boolean
  prefix: string
  onlyTool: string
}

export const Config: Schema<Config> = Schema.object({
  enabled: Schema.boolean().default(true),
  prefix: Schema.string().default('[tool-logger]'),
  onlyTool: Schema.string().default(''),
})

export function apply(ctx: Context, config: Config) {
  console.log(`${config.prefix} 插件已加载`)

  if (!config.enabled) {
    console.log(`${config.prefix} 日志功能已关闭`)
    return
  }

  let count = 0

  ctx.on('tools/result', (exec) => {
    if (config.onlyTool && exec.name !== config.onlyTool) {
      return
    }
    count += 1
    console.log(`${config.prefix} 第 ${count} 次记录：${exec.name}`)
  })
}

注意入口签名变成了 apply(ctx, config)——config 的来源见二.1 开头的说明。

2. 通过 YAML 传入配置

YAML
- insert:
    - id: lesson-tool-logger
      name: '/你的绝对路径/.../tool-logger.ts'
      config:
        enabled: true
        prefix: '[工具记录]'
        onlyTool: 'greet'

    - id: lesson-greet-tool
      name: '/你的绝对路径/.../greet-tool.ts'

重启后调用 greet，预期：

输出
[工具记录] 插件已加载
[工具记录] 第 1 次记录：greet

保存 YAML 后要重启（重建插件实例）再观察。不要只改文件就假定生效：最终生效的是叠加后的组合。

第 4 节

练习

练习 A（实现）：增加 maxLogs 配置（默认 5），达到上限后不再输出；只有匹配过滤条件的工具才计数；重启后归零。自测覆盖：默认只输出 5 条；maxLogs: 2 只输出 2 条；不匹配 onlyTool 的调用不占额度；重启从第 1 条重新开始。

练习 B（定位题）：某同学在两层里都配置了 tool-logger：

YAML
# bundle 层
config: { prefix: '[A]', onlyTool: 'greet' }

# --patch 层
config: { prefix: '[B]' }

重启后他发现 onlyTool 过滤失效了，所有工具都被记录。只改 patch 层的话，怎么让过滤重新生效？ 用"整体替换 + 回落默认值"解释原因，并说出两种修复方案。

完成后回答：

  1. maxLogs 为什么是配置？已输出次数为什么是状态？
  2. config 参数是谁传给 apply 的？依据是什么？
  3. 注册设置页时，为什么"滑块能拖动"≠"配置已保存"？

本章带走句

配置决定运行方式，状态记录运行过程，加载组合决定插件是否参与，插槽契约决定组件显示在哪里——后层覆盖是整体替换，没写的字段回落默认值。
