4A

事件：插件如何观察宿主

概念

apply(ctx) 的 ctx 由框架传入，是插件与宿主交互的入口。ctx 不是装好所有能力的全局对象：某个服务能否使用，取决于当前组合、inject 声明和作用域。

ctx.on(name, callback) 只登记回调，不立即执行；且回调只观察注册之后发生的事件——要查询过去，应读会话记录等历史数据，而不是指望监听补发。

Cordis 的事件派发有四种模式，监听器返回值的含义随模式不同：

模式行为返回值规则
emit广播通知忽略所有返回值
bail按顺序询问第一个非 null/false/undefined 的返回值成为结果并停止后续
serial顺序执行并等待异步停止规则同 bail
waterfall监听器串成处理链必须调用 next()，不调用会截断整条链（故意的拦截设计）

怎么知道某个事件属于哪种模式？查该事件的声明处或官方事件文档，不要按名字猜。 bail/serial 中返回 false 不是"否决"，它恰好表示"继续下一个"。

事件名不能凭印象写：tools/result 是 Cordis 运行时事件；tool/result 是持久化会话记录类型，不是事件。要观察后者，应监听 session/event 再检查 event.type。事后的结果事件也不能撤销已执行的操作。

操作：工具日志插件

创建 scratch-plugin/src/tool-logger.ts：

TypeScript
import type { Context } from '@deepseek-ai/cordis'
import '@deepseek-ai/dsh-tools'

export const name = 'tool-logger'

export function apply(ctx: Context) {
  console.log('[tool-logger] 已加载')

  ctx.on('tools/result', (exec) => {
    console.log(`[tool-logger] 工具执行结束：${exec.name}`)
  })
}

两个要点：

  • 第二行的裸导入（import '@deepseek-ai/dsh-tools'）没有绑定名字，作用是让 TypeScript 认识 tools/result 事件及 exec/result 的类型。删掉它，编辑器可能报"事件不存在"。
  • 回调实际接收 (exec, result)；本章只用 exec.name。需要判断成功失败或读取内容时用 result（如 result.isError、result.content），字段含义以契约为准。

在 cordis.yml 中加入条目后重启。终端出现"已加载"只证明第 3 格；要看到工具名称，还需要发生一次真实的工具执行（第 5 格的证据）。

4A 练习

实现：让日志插件只记录 greet，其他工具不输出（在回调开头 if (exec.name !== 'greet') return）。

定位题：你把裸导入那行删了，程序还能跑吗？编辑器里发生了什么？这说明这行导入影响的是哪一层（运行行为 / 类型检查）？

4B

工具：插件如何向模型提供能力

概念

服务是插件之间公开的能力（如 tools 服务挂在 ctx.tools 上）。模型不会直接调用 ctx.tools.register：插件注册工具 → 宿主把工具列给模型 → 模型请求调用 → 宿主执行 execute。注册成功只说明工具进入注册表（第 4 格），不等于被调用（第 5 格）。

defineTool 的四段结构：

部分作用说明
name / description调用标识与描述描述帮模型判断何时使用；应说明真实能力，不承诺没实现的行为
parameters参数契约defineTool 据此推导并校验 args
execute真正完成工作由宿主执行，模型不进入 Node 进程
output.schema + render返回值结构 + 转成模型可接收的内容块先符合 schema，再由 render 包装

工具描述不是权限控制：描述写"只读"而程序实现了写入，写入能力不会消失。

操作：注册 greet 工具

创建 scratch-plugin/src/greet-tool.ts：

TypeScript
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'greet-tool'

export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
    },
    output: {
      schema: { type: 'string' },
      render: (_args, value) => [{ type: 'text', text: value }],
    },
    async execute(args) {
      console.log('[greet-tool] 执行问候')
      return `Hello, ${args.name}!`
    },
  }))

  console.log('[greet-tool] 工具已注册')
}

在 cordis.yml 同一 insert 下追加条目，重启，然后在对话中输入：

请实际调用 greet 工具，向 Ada 问好。

正常调用应同时出现三类证据：

位置观察内容对应环节
对话过程实际的工具调用记录5 触发
宿主终端[greet-tool] 执行问候6 执行
宿主终端[tool-logger] 工具执行结束：greet4A 的监听生效

只看到模型输出 "Hello, Ada!"，不能证明工具被调用——模型也可能直接生成同样的文字。要结合调用记录和终端日志判断。

4B 练习

实现：给 greet 增加参数 language（zh/en），据此返回中文或英文问候；未提供按英文。

定位题：把 execute 里的 console.log 删掉，注册时仍然打印"工具已注册"。只看启动日志，你能区分"已注册"和"已被调用"吗？用一次真实调用说明你的判断依据。

4C

服务与 inject：apply 什么时候才被调用

概念

import 与 inject 解决不同的问题：

写法作用未满足时的表现
import { defineTool } from '...'从模块导入函数模块或导出不存在，加载阶段报错
export const inject = ['tools']声明运行必需的服务插件等待，不执行 apply

defineTool 是从包导入的函数；tools 是运行环境的服务名，不是导入来的对象。inject 让框架在服务就绪后再执行插件入口；必需服务的提供方被卸载时，依赖它的插件会被清理，服务恢复后重新加载。不写 inject 表示依赖可选，用 ctx.get('tools') 查询并自行处理找不到的情况。

生命周期与清理总表：

代码位置执行时机
apply 中的初始化语句插件激活时执行一次
ctx.on 注册的回调对应事件每次发生时
工具的 execute该工具被实际调用时
ctx.effect 返回的清理函数插件卸载或依赖失效时

4C 练习

实现：给 tool-logger 也加上 export const inject = ['tools']（它用到 @deepseek-ai/dsh-tools 的类型但不注册工具，观察行为是否变化）。

定位题：下面这个版本的 greet-tool，启动后终端一条日志都没有，也没有报错：

TypeScript
export const name = 'greet-tool'
// export const inject = ['tools']   ← 被注释掉了

export function apply(ctx: Context) {
  console.log('[greet-tool] 已注册')
  ctx.tools.register(/* ... */)
}

不查代码的话，症状是"插件像不存在一样"。请判断：卡在七环节图的哪一格？inject 被注释后，apply 还会被调用吗？把日志加在哪里能最早证明你的判断？

练习汇总

  1. import 导入了什么，inject 在等什么？
  2. execute 由谁触发，模型负责哪一部分？

本章带走句

注册 ≠ 调用——"已注册"的日志只能证明第 4 格；想证明工具真的跑了，去找 execute 的日志。没有 inject，apply 根本不会开始。
