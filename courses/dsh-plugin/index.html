全书主图

出问题时，先判断卡在第几格。

不是每章一个知识点，而是同一条链路被逐格点亮。

01安装包和相关文件是否存在？第 8 章
02加载当前运行配置是否引用了插件？第 3 章
03初始化入口是否执行，依赖是否就绪？第 3 章
04注册工具、监听或界面是否成功注册？第 4 章
05触发是否发生了预期的调用或事件？第 4 章
06执行程序是否完成操作？第 4 章
07展示结果是否返回到正确位置？第 6 章

怎么用这张图：学的时候，每章开头标注处理哪几格，学完自查“这几格我能不能独立走通”；用的时候，先判断卡在第几格，再去找那一格的证据。常见误区是跳格排查——“没有听到提示音”直接改播放函数，但问题可能出在第 2 格：压根没加载。

开课之前

先准备源码环境，再准备语言基础。

课程以源码 checkout 为主线，不是安装版 App。

适合谁

  • 已经会基本 JavaScript 或 TypeScript；没把握先做附录 A 的自测。
  • 用过 dsh，想理解它的插件到底怎样被加载和运行。
  • 需要把内部能力接进 dsh，或准备向别人分发插件。
  • 不要求先读 dsh 源码；但愿意查类型、读日志、做最小复现，会明显更顺。

课程环境

# 源码 checkout 是主线
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
git checkout 6c62d545bd
pnpm install --frozen-lockfile
pnpm run build

Node.js ^22.19.0 || >=24.0.0 · pnpm 11.7.0。所有 pnpm dsh ... 都在仓库根目录执行；已安装 CLI 的 dsh ... 与桌面 App 是另外两套环境，不要混用。

pnpm dsh / dsh

前者是源码仓库脚本，只在 checkout 根目录成立；后者是已安装的 CLI。桌面 App 走界面操作，不能默认终端里有 dsh。

Host / Client

Host 在宿主进程里运行，能读写文件、启动进程；Client 在浏览器页面里运行，只有 DOM、音频和插槽能力。

带走句 / 定位题

每章末尾一句加粗结论；定位题给你一份故意写坏的代码，先用日志和现象说清它坏在哪一层，再改到能跑。
