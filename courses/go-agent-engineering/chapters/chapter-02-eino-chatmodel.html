Eino 不让模型更聪明，
它让 AI 应用更像工程。

先用 Eino 完成一次标准模型调用，再理解组件、消息、上下文和 HTTP 服务之间的边界。

Eino 是什么

Gin 组织 HTTP 服务，Eino 组织模型、知识和行动。

Eino 是 CloudWeGo 开源生态中的 Go 大模型应用与 Agent 框架。它把模型调用、提示词、工具和资料检索连接起来。这里的“组件”就是承担一项工作的模块；“编排”就是安排这些模块按什么顺序执行。

Gin

路由、中间件、参数、鉴权和 HTTP 响应。

HTTP application framework

Eino

模型、消息、Prompt、知识检索、Tool 和编排。

LLM application framework

不用 Eino 也能调用模型，就像不用 Gin 也能用 net/http 写接口。框架的价值在项目复杂后才会真正出现。

为什么需要

直接调用一次模型 API 很简单，维护完整 AI 应用并不简单。

flowchart LR
    U[用户问题] --> P[Prompt]
    P --> M[模型]
    M --> D{还需要什么}
    D -->|实时数据| T[Tool]
    D -->|私有知识| R[Retriever]
    D -->|可以回答| A[答案]
    T --> M
    R --> M
    A --> S[保存会话 / 流式返回 / Trace]

统一组件

业务代码面向 ChatModel、Tool、Retriever 等抽象，而不是散落的供应商 HTTP 调用。

统一编排

Chain、Graph、Workflow 和 Agent 负责组织步骤、分支、循环和流式数据。

统一治理

Callback（回调）是在步骤开始、完成或失败时执行的记录函数；Trace（执行记录）把这些步骤串起来，帮助找到慢在哪里、错在哪里。

核心组件地图

先知道每个组件解决哪类问题。

组件职责学业助手中的位置

模型初始化

项目启动时，根据配置创建一个 ChatModel。

backend/internal/agent/agent.go项目源码
chatModel, err := openai.NewChatModel(ctx, &openai.ChatModelConfig{
    Model:   model,
    APIKey:  apiKey,
    BaseURL: baseURL,
})
if err != nil {
    return nil, fmt.Errorf("初始化ChatModel失败: %w", err)
}

agent.go 不直接读取环境变量，而是接收已经解析好的配置。模型创建、业务服务组装和 HTTP 启动因此保持了清晰边界。

.env · 本地开发对应 config/config.go
DEEPSEEK_API_KEY=your_api_key
DEEPSEEK_MODEL=deepseek-chat
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1

消息怎样传入

告诉模型“按什么规则做”和“这次做什么”。

System 消息放应用规则，User 消息放本轮问题，模型返回的 Assistant 消息就是回答。沿用前面初始化的 chatModel，在 Go 函数内继续执行：

输入消息 → 调用模型 → 读取回答调用片段
messages := []*schema.Message{
    schema.SystemMessage("只依据提供的成绩回答；没有数据时说明不知道。"),
    schema.UserMessage("张三：数学 90 分，数据结构 72 分。哪门课分数较低？"),
}
response, err := chatModel.Generate(ctx, messages)
if err != nil {
    return fmt.Errorf("生成回答失败: %w", err)
}
fmt.Println(response.Content)

应能得到“数据结构较低，72 分”这样的结论，措辞可以不同。这里的成绩由消息提供；接入数据库查询将在第 4 章完成。

调用方式参见 Eino ChatModel 使用说明。

Go 工程习惯

让一次模型调用能超时、能取消，也能逐段返回。

模型“上下文”指这次交给模型的消息和资料；Go 的 context.Context 用来传递取消信号、超时等请求信息。两者名字相似，用途不同。

能力解决什么问题
Context把超时、取消、Trace 和请求级数据贯穿模型与组件调用
Generate等待完整消息生成后一次返回，最适合第一版和后台任务
Stream边生成边返回，适合聊天页面和长回答
错误处理区分配置错误、模型失败、超时和用户取消
请求级超时Go
ctx, cancel := context.WithTimeout(parent, 20*time.Second)
defer cancel()

response, err := chatModel.Generate(ctx, messages)
if errors.Is(err, context.DeadlineExceeded) {
    return fmt.Errorf("模型调用超时")
}

Eino 与 Gin

Gin 接收请求，Eino 执行 AI 业务。

flowchart LR
    F[前端] -->|HTTP| G[Gin Handler]
    G --> S[业务 Service]
    S --> E[Eino App / Agent]
    E --> M[ChatModel]
    E --> K[Retriever]
    E --> T[Tool]
    E --> S
    S --> G
    G --> F

本页总结

  1. Eino 是 Go 大模型应用与 Agent 工程框架，不是模型和 Web 框架。
  2. 组件解决单项能力，编排负责把组件组织成应用。
  3. Message 的角色结构比字符串拼接更可靠。
  4. Context、错误处理和流式输出是 Go AI 工程的基础。
  5. Gin 管 HTTP，Eino 管 AI 调用链，两者处在不同层次。

小练习

先给成绩，再撤掉成绩。

  1. 用上面的消息完成一次调用，记录回答。
  2. 把 User 消息改为“张三的数据结构多少分？”，不提供成绩，再调用一次。
  3. 比较两次回答：第二次是否明确说明缺少数据？

完成标准：能指出规则、问题和回答分别在哪个变量中；理解模型不能靠一次调用自动获得业务数据。
