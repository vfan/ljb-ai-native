项目拓展，不是仓库现状

当前 eino-oa 通过 Tool 查询结构化业务数据，尚未实现 Retriever、Embedding 和向量索引。本章先建立设计判断，后续再把它实现成新的业务能力。

先区分知识来源

训练数据不是业务数据库，也不是学校知识库。

问题正确来源接入方式
张三的数据结构成绩是多少？成绩数据库Tool / API 精确查询
2026 级学生毕业需要多少学分？培养方案文档Retriever 检索相关条款
请解释什么是 goroutine模型通用知识ChatModel 直接回答

先判断事实来自哪里，再决定使用模型、Tool 还是 Retriever。不要把所有信息都塞进向量数据库。

先把两个概念分开

Retriever 找资料，RAG 用资料生成答案。

Retriever · 检索器

接收一个问题，从知识库中找出相关文档片段。

问题 → 相关资料

RAG · 检索增强生成

先检索资料，再让大模型根据资料组织答案。

问题 → 资料 → 答案
对比RetrieverRAG
它是什么一个检索组件一套完整问答流程
主要工作找到相关资料找资料，并基于资料回答
是否必须调用大模型不一定通常需要
直接输出文档、片段和元数据自然语言答案和引用来源
直观类比图书管理员图书管理员 + 阅读并讲解资料的老师

Retriever 是 RAG 中负责“找资料”的部分，但 Retriever 本身不等于完整的 RAG。

RAG 的两条链路

文档先建立索引，提问时再检索相关片段。

flowchart TB
    subgraph INDEX[索引阶段]
      D[培养方案 / 学生手册] --> S[文档切分]
      S --> E[Embedding]
      E --> V[(向量索引)]
    end
    subgraph QUERY[问答阶段]
      Q[用户问题] --> QE[问题 Embedding]
      QE --> R[Retriever]
      V --> R
      R --> C[相关文档片段]
      C --> P[Prompt + 用户问题]
      P --> M[ChatModel]
      M --> A[带来源的回答]
    end

索引阶段把文档加工成可检索的数据，通常在文档新增或更新时执行。问答阶段从索引中找出与当前问题相关的片段，每次提问都会执行。

Retriever 怎样找资料

关键词、向量和混合检索解决的问题不同。

方式怎样匹配擅长什么可能的问题
关键词检索比较问题和文档中的词语课程编号、文件名称、专业术语换一种说法可能搜不到
向量检索比较两段文字的语义距离自然语言和相近表达精确编号和专有名词可能不稳定
混合检索合并关键词与向量结果，再统一排序同时兼顾精确匹配和语义理解实现和调优更复杂

同一个问题，两种检索看到的内容不同

“大三评奖需要满足什么条件？”与文档中的“本科三年级奖学金评定要求”用词不同，向量检索更容易发现它们语义相近；而查询课程编号 CS101 时，关键词检索通常更可靠。

生产系统经常采用混合检索：关键词负责“字面准确”，向量负责“意思接近”。

Embedding

向量用于比较语义，不是保存答案。

原始文本

毕业需要修满多少学分？

文字不同，关键词可能不完全一致。

语义向量

[0.12, -0.37, 0.81, ...]

和“本科毕业学分要求”语义接近，可以被相似度检索找到。

Embedding 模型也要版本化

索引和查询必须使用兼容的 Embedding 模型。更换模型后，旧向量通常需要重新生成，不能只改一行配置。

Retriever 的职责边界

Retriever 返回资料，不负责写最终答案。

Document · 结构示意Go
document := &schema.Document{
    ID:      "training-plan-2026-page-12",
    Content: "学生完成培养方案规定课程，并修满 160 学分方可毕业。",
    MetaData: map[string]any{
        "title": "2026 级计算机专业培养方案",
        "page":  12,
        "year":  2026,
    },
}

元数据就是文本以外的附加信息，例如标题、年份和页码，可以用于筛选、权限检查和引用。回答“毕业学分要求”时，页面应该同时展示文档名称、页码和版本，而不是只给出一句无法核验的结论。

不要把 Retriever 等同于向量数据库

数据库保存和查询向量，Retriever 组织整个检索过程。

flowchart LR
    Q[用户问题] --> W[问题改写]
    W --> K[关键词检索]
    W --> E[生成 Embedding]
    E --> V[(向量数据库)]
    K --> H[合并与排序]
    V --> H
    H --> F[权限与版本过滤]
    F --> D[相关文档片段]

向量数据库只是 Retriever 可能调用的基础设施之一。Retriever 还可以改写问题、同时调用全文检索、合并结果、过滤无权查看的文档，再返回最相关的片段。

Retriever 也可以独立用于站内搜索：如果系统只展示搜索结果，没有把资料交给大模型生成答案，这就是检索，不是 RAG。

用 Go 代码看清边界

一次 Retrieve 是检索；检索、构造上下文和生成合起来才是 RAG。

只使用 RetrieverGo
query := "2026 级学生毕业需要多少学分？"

documents, err := retriever.Retrieve(ctx, query)
if err != nil {
    return err
}

// 这里只展示检索到的资料，还没有生成答案。
for _, document := range documents {
    fmt.Println(document.Content)
}
完整 RAG · 流程示意Go
query := "2026 级学生毕业需要多少学分？"

// 1. Retriever 找到相关资料
documents, err := retriever.Retrieve(ctx, query)
if err != nil {
    return "", err
}

// 2. 把文档片段整理成模型可读的上下文
knowledge := buildKnowledgeContext(documents)

// 3. ChatModel 根据资料生成答案
answer, err := chatModel.Generate(ctx, []*schema.Message{
    schema.SystemMessage(
        "请只根据给定资料回答；资料不足时明确说明不知道。",
    ),
    schema.UserMessage(fmt.Sprintf(
        "资料：\n%s\n\n问题：%s",
        knowledge,
        query,
    )),
})
if err != nil {
    return "", err
}

return answer.Content, nil

在 Eino 中，Retriever 可以作为独立组件使用；完整 RAG 则可以用 Chain 或 Graph 把 Retriever、上下文构造、Prompt 和 ChatModel 编排起来。

Tool 与 RAG 的边界

结构化实时数据用 Tool，非结构化知识用 Retriever。

维度ToolRetriever / RAG
数据类型数据库字段、实时状态、业务动作手册、制度、合同、课程资料
结果精确结构化数据与问题相关的文本片段
例子查询成绩、录入成绩解释奖学金规则、毕业要求
主要风险越权与副作用召回错误、过期文档和提示注入

RAG 质量不是只看“能不能搜到”

切分、召回、权限、时效和引用缺一不可。

Chunk · 文档片段

把长文档分成小段。段落过长会带入无关内容，过短可能切掉条件和例外。

TopK · 取回几段

例如 TopK=3 表示最多取回三个相关结果。太少可能漏答案，太多可能混入无关内容。

Metadata Filter · 按附加信息筛选

按院系、年份、文档状态和用户权限过滤。

检查项工程要求
来源回答中保留文档标题、版本和页码
时效新培养方案发布后能够重建或增量更新索引
权限无权访问的文档不能进入 Retriever 结果
无答案没有可靠片段时明确说不知道，不让模型补写

本页总结

  1. 模型通用知识、业务数据和私有文档来自不同事实源。
  2. Embedding 把文本变成语义向量，Retriever 找到相关片段。
  3. RAG 是先检索再生成，回答应保留来源。
  4. 结构化实时数据优先用 Tool，非结构化知识优先用 Retriever。
  5. RAG 还要处理权限、版本、时效、无答案和提示注入。

小练习

先判断去哪找，再判断能否回答。

为“张三的成绩”“2026 级毕业学分”“什么是 goroutine”分别选择数据库查询、文档检索或模型解释。

再假设知识库只有 2025 级培养方案，用户问 2026 级要求。写出应返回的说明，以及缺少哪份资料。

完成标准：成绩来自业务数据，规则附有适用年份和来源；没有对应资料时说明缺失，不套用旧规定。
