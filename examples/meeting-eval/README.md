# 会议助手 · 提示词评测台

本仓库 `examples/` 下的配套评测项目，作为《服务端 Agent 开发实践》[第 9 章：测试与验收学业助手](../../courses/go-agent-engineering/chapters/chapter-09-evaluation-contract.html)的选做实验，同时用于《AI Native 产品设计》第 10 课。它把「评什么、怎么评、评完怎么改」做成一个能点开的平台：一个会议行动项提取任务、两版提示词、14 条边界样本、规则评分 + AI 裁判、版本对比和发布门禁。它检查单次输出，学业助手的多步工具执行需另行检查。

- 场景固定：从会议记录里提取行动项，判断负责人、截止时间和**承诺状态**
- 一次只改一个变量：模型、温度、数据集、评分器都不动，只换提示词
- 硬性错误单独统计：编造负责人、把建议当承诺、遗漏任务不会被平均分掩盖
- 零第三方依赖：Go 标准库 + 内嵌前端，`go run .` 就能跑

## 快速开始

要求 Go 1.22+。以下命令在仓库根目录执行。

```bash
cd examples/meeting-eval
go run .
# 打开 http://127.0.0.1:8765
```

没有 API key 时自动进入**回放模式**：用预置输出走完整链路，延迟与成本是模拟值，界面上有明确标记。

接真实 DeepSeek：

```bash
cp .env.example .env      # 填入 DEEPSEEK_API_KEY
go run .
```

模型默认用 `deepseek-flash`（DeepSeek-V4.1-Flash）；需要更强推理时可改成 `deepseek-v4-pro`。请求里显式关闭了 thinking 模式，因为行动项抽取和逐条判定不需要思维链。

也可以在启动时用环境变量覆盖：`EVAL_MODE=live EVAL_MODEL=deepseek-flash EVAL_PORT=9000 go run .`。

### 30 秒看完整故事

1. 在「运行」页选 **v1 朴素版**，点开始运行
2. 再选 **v2 规则版**，点开始运行（页面会自动跳到对比）
3. 回放模式的对比页会看到：通过率约 36% → 93%，硬性错误 9 条 → 1 条，另有 1 条退步
4. 默认门槛为通过率 ≥ 85%、硬性错误 ≤ 1 条、回归 = 0；回放候选版仍有 1 条退步，因此显示「需要人工确认」。去「发布门禁」把允许的硬性错误改成 0，同一份结果会立刻被阻断
5. 点仍然失败的样本，右侧抽屉里对照原文、两次输出和评分依据

门槛根据任务风险确定。回放输出是预置的教学数据；真实效果需固定条件后用 live 模式重新运行。

## 它对应课程里的哪些点

| 章节 | 平台里的实现 |
|---|---|
| 一次成功不等于可靠 | 14 条边界样本，覆盖正常、缺失、模糊、变更、取消、无行动项 |
| 把抽象要求改写为可检查条件 | 输出契约 `task/owner/due/status/evidence` + 硬性错误清单 |
| 硬门槛与质量要求 | 硬性错误直接判失败；措辞、缺失依据等只扣质量分 |
| 测试集覆盖真实差异 | 6 类场景、6 个切片，含相对日期与缩写 |
| 三种评分方法 | 程序规则 + AI 裁判（回放时为本地启发式）+ 可复核的依据 |
| AI 评分要给依据 | 裁判逐条返回判定、原文片段、错误类型，而不是只打总分 |
| 比较版本要看退步 | 用例迁移四分类：修复 / 保持通过 / 退步 / 仍然失败 |
| 平台让评测可重复、可追溯 | 提示词版本、模型参数、数据集和结果全部落盘快照 |
| 评完怎么改 | 从失败类型定位到提示词规则，再跑一次验证 |

## 评分是怎么做的

**输出契约。** 每条行动项必须给出任务、负责人、截止时间、承诺状态和原文依据。承诺状态只有三个值：

- `confirmed`：明确承诺、明确分派或已经确认
- `pending`：询问、建议、试探、信息缺失
- `cancelled`：明确取消

**期望结果是约束，不是标准答案。** 样本里写的是「任务需包含哪些词、负责人是谁或必须留空、截止时间是哪一天、状态是什么」，不要求措辞一致。`change-2` 允许合理的额外行动项，`none-1` 则要求严格返回空数组。

**硬性错误（任一触发即该条失败）：**

| 类型 | 含义 |
|---|---|
| `fabricated_owner` | 原文没有负责人，输出却给了名字 |
| `fabricated_due` | 原文没有截止时间，输出却补了日期 |
| `false_commitment` | 把「能不能」「尽量」「看看」标成已确认 |
| `cancelled_as_todo` | 已取消的事项仍被当成待办 |
| `missed_item` | 遗漏原文中已确认的行动项 |
| `wrong_due` / `wrong_owner` | 与最终决定不符 |
| `unsupported_claim` | 无原文依据的行动项，或会议本无行动项却强行生成 |
| `invalid_output` | 结构或枚举值不合法 |

措辞冗长、缺少原文依据、已确认标成待确认等只扣质量分，不直接判死。

**三种评分来源。** 规则先检查结构、字段、日期与状态；AI 裁判再检查任务是否被原文支持、是否遗漏、是否误判承诺；结果里保留检查项、错误类型和裁判理由，便于人工复核争议样本。

**回放模式。** 没有 key 时，模型输出由 `internal/eval/replay.go` 按每个样本的教学目的预置：v1 会补人补时间、把建议当承诺、把取消当待办；v2 修掉大部分问题，但在一件事上过度保守，留下一条回归。这组数字用来演示方法与流程，不代表真实模型的测量结果。

## 目录

```
examples/meeting-eval/
├── main.go                  # HTTP 服务、内嵌前端、启动参数
├── internal/eval/
│   ├── types.go             # 提示词、样本、运行、结果、门禁
│   ├── store.go             # 单文件 JSON 存储（可替换为 SQLite）
│   ├── seed.go              # 两版提示词 + 14 条样本
│   ├── replay.go            # 回放模式的预置输出
│   ├── llm.go               # DeepSeek / OpenAI 兼容调用
│   ├── judge.go             # 启发式裁判 + LLM 裁判
│   ├── rule.go              # 规则评分、日期归一化、状态判定
│   ├── runner.go            # 并发执行、快照、进度
│   ├── metrics.go           # 指标、场景切片、回归、门禁
│   └── api.go               # JSON API
├── web/                     # 原生 HTML/CSS/JS，go:embed 进二进制
├── .env.example
└── README.md
```

运行时数据写在 `data/store.json`，删掉即可回到干净的初始状态。

## API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/bootstrap` | 提示词、数据集、样本、运行记录、门槛 |
| POST | `/api/runs` | 创建并异步执行一次运行 |
| GET | `/api/runs/{id}` | 运行状态与进度 |
| GET | `/api/compare?baseline=&candidate=` | 指标、切片、迁移、门禁 |
| GET | `/api/case?slug=&baseline=&candidate=` | 单条样本的原文、两次输出与判定 |
| GET/POST | `/api/gate` | 查看或记录发布判定 |

```bash

```

覆盖相对日期换算、无依据补全、假承诺、取消误判、无行动项幻觉，以及一次完整的回放对比（5/14 → 13/14、1 条回归、门禁 review）。

## 已知边界

- 存储是单文件 JSON，适合演示与单团队小规模；上量后换 SQLite/Postgres，只需替换 `store.go`
- 没有人工评审任务队列，只在结果里保留复核所需的证据与错误类型
- 单输出评分，没有做 A/B 盲评与顺序消除（评测章节提到的裁判偏差）
- 没有接 CI 与线上日志回流；`POST /api/runs` 可以被 CI 直接调用，但流水线配置不在本演示范围

更完整的设计取舍见 [DESIGN.md](DESIGN.md)。
